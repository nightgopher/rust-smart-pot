# 🪴 Rust Smart Pot · 智能养花系统

> 基于 ESP32 + Rust 的物联网智能植物养护系统：环境监测、自动浇水、远程控制、历史数据分析与植物健康识别。

本项目是一个以「练 Rust」为核心目标的实战项目，同时覆盖 **嵌入式 / IoT / 后端 / 前端 / AI** 全链路，最终目标是做出一个真正可以落地、甚至有机会产品化的系统。

---

## 🎯 项目目标

做一个「即使断网，花也不会死」的智能花盆。

| 能力 | 说明 |
| --- | --- |
| 环境监测 | 采集土壤湿度、空气温湿度、光照强度 |
| 自动浇水 | 土壤过干时自动启动水泵，带滞回与冷却保护 |
| 远程控制 | 网页端查看花盆状态、手动触发浇水 |
| 数据分析 | 历史曲线、每日浇水次数统计 |
| 边缘智能 | 断网时花盆仍可自主浇水（核心原则） |
| 进阶 AI | 摄像头拍照、叶片健康识别、病虫害检测 |

## 🏗️ 架构设计

### 核心原则：边缘智能优先

> **服务器挂了、Wi-Fi 断了，花也不能死。**

所有关键浇水逻辑必须在设备本地执行，云端只做**监控、记录、增强**。正确的设计是：

```
┌─────────────────────────────┐        ┌─────────────────────────────┐
│         设备端 (ESP32)       │        │        服务器端 (Rust)       │
│                             │        │                             │
│  传感器采集 → 本地阈值判断   │ HTTP/  │  接收数据 → 存储 → 判断报警  │
│  本地自动浇水 (断网可用)     │  MQTT  │  下发远程命令 / 管理多花盆   │
│  最多每 N 秒上传一次快照     │ ─────► │  生成生长报告 / 可视化面板   │
│  接收并执行远程浇水命令      │        │                             │
└─────────────────────────────┘        └─────────────────────────────┘
                                                  │
                                                  ▼
                                        ┌───────────────────┐
                                        │   Web 管理后台    │
                                        │ 状态 / 曲线 / 操作 │
                                        └───────────────────┘
```

### 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 固件 | ESP32（先用成熟方案 C/Arduino，稳定后再考虑 `esp-rs`） | 入门阶段优先稳定性 |
| 通信 | 第一阶段 HTTP，后期升级 MQTT | HTTP 更简单，MQTT 适合设备长连接 |
| 后端 | **Rust** + `axum` + `tokio` | 练 Rust 的核心战场：异步、trait 抽象 |
| 数据库 | 先 SQLite（单设备），后期 PostgreSQL | 时序数据量不大，不必一开始上专业 TSDB |
| ORM | `sqlx`（编译期 SQL 校验） | 类型安全，练 Rust 的 trait/宏 |
| 实时 | `WebSocket` 推送浇水事件到前端 | 练 Rust 异步 channel |
| 前端 | 轻量前端（后续定） | 展示状态与曲线 |

## 🔩 硬件清单

适合入门的一套配置：

- **ESP32** 开发板（主控 + Wi-Fi）
- **电容式土壤湿度传感器**（⚠️ 不要用电阻式探针，长期插土易腐蚀、数据漂移）
- 温湿度传感器：**DHT22** 或 **SHT30**
- 光照传感器：**BH1750**
- 小型水泵 + 继电器（或 MOS 管模块）
- 水管、水箱
- 5V 或 12V 电源（⚠️ 水泵必须独立供电，不要用 ESP32 的 IO 直接驱动）
- 面包板、杜邦线
- （强烈建议）**水箱低水位传感器**，防止水泵干烧

## 🧠 核心设计要点（避免踩坑）

这部分是区分「玩具」和「能落地系统」的关键。

### 1. 浇水逻辑：状态机 + 滞回（Hysteresis）+ 冷却

**不要用单纯阈值判断**，否则传感器抖动会让水泵频繁启停。

- **滞回比较**：湿度 `< 30%` 开始浇水，`> 60%` 才停止，中间区间保持原状态。
- **冷却期**：浇完水后强制等待 10~30 分钟再测量，让水渗透。
- **状态机**：`IDLE → 检测中 → 浇水中 → 冷却中`，状态互斥。

```
        ┌──────┐  湿度<30%  ┌────────┐
        │ IDLE │ ─────────► │ 浇水中  │
        └──────┘            └────────┘
            ▲                   │
            │ 冷却结束           │ 湿度>60% 或 超时
   ┌────────┴───────┐           ▼
   │   冷却中        │ ◄────── (强制等待10~30min)
   └────────────────┘
```

### 2. 土壤湿度需要校准

传感器读数不是「30% 就一定干」。不同土壤、花盆、插入深度都会影响数据：

1. 干土中读取原始值 → 记为 `dry_raw`
2. 水中读取原始值 → 记为 `wet_raw`
3. 映射成 `0% ~ 100%`

### 3. 不能只看瞬时读数

传感器会波动，应连续读取多次（如 5 次）取平均或去极值后再判断。

### 4. 必须有浇水保护

防止传感器损坏导致水泵一直开着（后果：水漫金山 / 水泵干烧）：

- 单次浇水最大运行时长（如 60 秒强制停）
- 每日浇水次数上限
- 水泵独立供电
- 水箱低水位报警（优先级最高）

### 5. 远程浇水要限频 + 鉴权

手动浇水接口强制冷却（如 5 分钟），并做鉴权，避免被滥用或 bug 触发。

## 🗺️ 开发路线（六阶段）

不一开始做完整产品，分阶段推进：

### 阶段一 · 让水泵工作
- 先不接传感器
- 用代码控制继电器/MOS 管开关水泵
- 验证供电与驱动电路

### 阶段二 · 读取土壤湿度
- 接传感器，连续读取取平均
- 观察干土 / 湿土的数据差异
- 完成校准（`dry_raw` / `wet_raw`）

### 阶段三 · 自动浇水
- 实现「状态机 + 滞回 + 冷却」
- 加入浇水间隔与最大运行时长保护
- 确保断网也能正常工作

### 阶段四 · 联网
- ESP32 上报数据到 Rust 后端
- 后端存储历史数据
- 下发远程浇水命令

### 阶段五 · 管理后台
- 展示当前湿度、温湿度曲线
- 浇水记录
- 手动浇水按钮（带限频）

### 阶段六 · AI 与摄像头
- 拍照 / 生长延时摄影
- AI 判断叶片是否发黄、病虫害识别
- 花卉种类识别、按植物类型推荐阈值
- 根据天气调整浇水量

### 未来的可扩展方向
- 多花盆管理 · 自动补光 · 自动施肥 · 语音控制 · 水箱低水位提醒
